# 一、文件目的與邊界

本文件回答：使用者在 04 文件完成操作後，系統如何依固定步驟執行、判斷、等待、重試、取消、補償與恢復；哪些狀態是正式事實；哪些步驟需要人工確認；哪些失敗可以自動恢復，哪些必須停止並交由人工處理。

本文件同時描述 User Workflow、Business Workflow 與 Technical Workflow，但暫不綁死特定 AWS 服務、資料表、API 路徑或訊息格式。後續 06 Domain Model、07 Security／Privacy、08 AWS 系統架構、09 Agent 設計及 10 API／Event／Data Contracts 將把本文件轉成可實作規格。

本文件不允許 Agent 自行繞過同意、權限、Schema、安全檢查、Eligibility 或人工核准；也不允許將陪伴互動轉化為醫療診斷、治療建議或自動修改正式照護計畫。

# 二、工作流分層

## 2.1 User Workflow

描述長者、日照照服員、居服員、家屬與管理者可觀察到的操作、等待、成功、失敗與返回路徑。

## 2.2 Business Workflow

描述候選事件、摘要、記憶、派案、報表、通知、同意及刪除工作如何改變正式業務狀態。

## 2.3 Technical Workflow

描述同步與非同步節點、確定性規則、模型節點、資料寫入、Outbox、重試、DLQ、補償與稽核；不在此階段指定 Lambda、Step Functions、SQS 或其他實作服務。

# 三、共同設計規則

1. 交易事實來源：同意、權限、派案、正式事件、正式記憶、報表版本、通知狀態與待辦以交易型資料庫為事實來源；Graph DB、搜尋索引與快取是可重建投影。

2. AI 與確定性程式分工：語意擷取、摘要草稿、候選話題與自然語言生成可使用模型；日期、權限、同意、狀態轉移、Schema、重試次數、通知條件與冪等由確定性程式控制。

3. 寫入前驗證：結構化輸出必須通過 Schema、ownership、tenant／elder 權限、同意版本及安全檢查。

4. 至少一次投遞：非同步事件允許重送，但所有消費者必須依 idempotency_key 去重。

5. 不以重試掩蓋錯誤：可恢復錯誤才重試；權限不足、同意缺失、Schema 不合法或人工拒絕不得自動重試成成功。

6. 人工確認優先：未確認記憶、低信心關鍵事件、家屬分享內容與敏感主動陪伴不得自動成為正式結果。

7. 取消與撤回優先：使用者取消、拒絕或撤回同意後，不得因排程、重試或佇列延遲繼續建立新結果。

8. 資料隔離：所有讀寫、Graph 查詢、摘要、報表與通知均需綁定 elder_id、tenant_id、actor_id 與 authorization_scope。

9. 觀測與最小化：保留 trace、狀態、reason_code、版本與必要證據識別，不在日誌保存不必要完整敏感逐字稿。

10. 失敗可見：系統不得把逾時、空結果或同步失敗假裝成已完成。

# 四、共同識別碼與版本欄位

• trace_id：跨服務追蹤同一使用者操作或背景工作。

• workflow_instance_id：識別一次工作流執行。

• idempotency_key：避免重送造成重複事件、記憶、報表或通知。

• elder_id／tenant_id：長者與照護單位隔離鍵。

• actor_id／actor_role：發起或處理工作的人與角色。

• consent_version：本次處理實際使用的同意版本。

• policy_version：本次決策使用的規則版本。

• model_version／prompt_version：模型節點的可追溯版本。

• event_id／memory_id／report_id／notification_id／assignment_id：正式業務物件識別。

• source_ids：可回查來源事件、逐字稿片段、記憶或文件版本。

• created_at／updated_at／expires_at：建立、更新與失效時間。

• reason_code：阻擋、拒絕、失敗、取消、排除或人工決策原因。

# 五、共同錯誤分類與恢復原則

## 5.1 不重試

• AUTHORIZATION_DENIED：權限不足，立即停止且不顯示敏感資料。

• CONSENT_MISSING／CONSENT_REVOKED：缺少或已撤回同意，停止對應用途。

• VALIDATION_ERROR：Schema 或業務規則不合法，回到產生端修正一次或進人工處理。

• USER_REJECTED／CANCELLED：尊重使用者選擇，不自動重開流程。

• ASSIGNMENT_EXPIRED：派案已失效，返回行程入口。

• SAFETY_BLOCKED：命中安全或醫療紅線，使用安全回覆，不嘗試繞過。

## 5.2 可有限重試

• TRANSIENT_NETWORK_ERROR：採退避策略重試。

• DEPENDENCY_TIMEOUT：同步互動最多一次，背景工作最多三次。

• RATE_LIMITED：等待指定時間後重試。

• GRAPH_PROJECTION_FAILED：正式交易不回滾，投影事件重試或進 DLQ。

• NOTIFICATION_SEND_FAILED：報表仍維持 Published，只重試通知。

## 5.3 需人工處理

• RETRY_EXHAUSTED：超過上限後進 DLQ 或 Needs Manual Action。

• DATA_CONFLICT：資料版本衝突、來源互相矛盾或多方同時修改。

• PARTIAL_DELETE_FAILURE：部分衍生資料刪除失敗。

• SENSITIVE_CONTENT_REVIEW_REQUIRED：家屬分享或主動陪伴內容需要專業照護者核准。

# 六、核心狀態機

## 6.1 語音 Session

IDLE → RECORDING → ASR_PROCESSING → LOW_CONFIDENCE_CONFIRMATION（必要時）→ GENERATING → SAFETY_CHECK → TTS_PROCESSING → PLAYING → COMPLETED

任何處理狀態可轉為 CANCELLED、TIMED_OUT 或 FAILED；失敗後只允許明確 Retry 或 Return to Idle，不得無限循環。

## 6.2 候選事件

CANDIDATE → NEEDS_REVIEW → VERIFIED／CORRECTED／REJECTED → SUPERSEDED

只有 VERIFIED 或經規則允許的 CORRECTED 事件可進入正式摘要、家屬報表及 Graph 投影。

## 6.3 確認式記憶

CANDIDATE → PENDING_CONFIRMATION → CONFIRMED／REJECTED／DEFERRED → ACTIVE → INACTIVE → DELETED

只有 ACTIVE 記憶可被檢索；DEFERRED 不得在後續對話當成事實。

## 6.4 Graph 投影

PENDING → PROCESSING → SYNCED

失敗分支：PROCESSING → FAILED → RETRYING → SYNCED／DEAD_LETTER

Graph 失敗不改變 RDS 內已確認事實；修復後以 Outbox 重放重建投影。

## 6.5 家屬報表

DRAFT → NEEDS_REVIEW → PUBLISHED → WITHDRAWN

家屬只能看到 PUBLISHED；敏感內容必須經 NEEDS_REVIEW 與人工核准。

## 6.6 通知

PENDING → SENDING → SENT → OPENED

失敗分支：SENDING → FAILED → RETRYING → SENT／DEAD_LETTER → NEEDS_MANUAL_ACTION

## 6.7 居服派案

SCHEDULED → CONFIRMED → IN_PROGRESS → COMPLETED

替代狀態：CANCELLED、EXPIRED、NO_SHOW。只有有效派案可讀取服務所需資料。

## 6.8 同意與刪除

ACTIVE → REVOKE_REQUESTED → REVOKED

資料處理：QUEUED → PROCESSING → COMPLETED

失敗分支：PROCESSING → PARTIAL_FAILURE → RETRYING／NEEDS_MANUAL_ACTION → COMPLETED

撤回一旦確認，停止新增對應用途不需等待刪除完成。

## 6.9 主動陪伴 Trigger

CREATED → ELIGIBILITY_CHECK → BLOCKED／APPROVAL_REQUIRED／ELIGIBLE → SCHEDULED → GENERATING → SAFETY_CHECK → READY → PLAYING → COMPLETED

替代狀態：POSTPONED、CANCELLED、EXPIRED、FAILED。任何到期 Trigger 都必須重新通過 Eligibility。

# 八、WF-01｜長者語音互動與低信心確認

### 目的

讓長者以一次主要操作完成語音互動，在聽不清楚、逾時或服務失敗時仍能安全返回，不把不確定內容寫成正式事件或記憶。

### Trigger

長者在語音首頁按下開始錄音，或在允許的主動陪伴 Session 中回應。

### Actors

長者、Conversation Orchestrator、Speech Router／ASR、Companion Agent、Safety Evaluator、TTS、Event／Memory Extractor。

### 前置條件

• 有效基本語音同意。

• elder_id、語言偏好與 authorization scope 可讀取。

• 麥克風已授權；否則停在 UX 引導，不建立 Session。

• 沒有另一個進行中的語音 Session。

### Happy Path

1. 建立 audio_session_id、workflow_instance_id、trace_id 與 idempotency_key。

2. 狀態進入 RECORDING，長者主動結束或達最長錄音時間。

3. Speech Router 依 Persona、Session 語言與明確切換指令選擇 ASR。

4. ASR 產生 final transcript、confidence、model_version 與關鍵欄位信心。

5. 若人物、日期、否定、用藥陳述等關鍵欄位低信心，轉入 LOW_CONFIDENCE_CONFIRMATION。

6. 長者確認後才把修正後逐字稿交給 Orchestrator；否認或仍不清楚時，不建立正式事件與記憶。

7. Orchestrator 組合最小必要 Context，Companion Agent 產生簡短回覆。

8. Safety Evaluator 檢查醫療紅線、隱私、ownership 與內容限制。

9. TTS 產生首段音訊並播放；TTS 失敗時保留文字並允許重播。

10. 非同步觸發事件擷取與候選記憶，不阻塞長者聽到主要回覆。

11. Session 完成並保存必要 metrics、trace 與實際使用的 Context IDs。

### 分支與恢復

• 麥克風拒絕：不建立音訊，顯示授權引導。

• ASR 無結果：請長者重說一次；再次失敗回到 Idle。

• LLM 或 Safety 失敗：最多修正一次，再使用固定安全回覆。

• TTS 失敗：顯示文字，提供重新播放或稍後再試。

• 長者取消：立即停止後續生成；已上傳音訊依保留政策處理。

### Timeout／Retry

ASR timeout 5 秒、LLM timeout 10 秒、TTS timeout 5 秒；同步自動重試各最多一次，沿用同一 idempotency_key。

### 對應需求與 UX

US-A01～A06、US-B01、US-D01；04 文件 6.2、6.3、7.1、8.1。

### 完成證據

林阿嬤可重跑一條正常國臺混語流程、一條低信心確認流程及一條 ASR／TTS 降級流程。

# 九、WF-02｜事件覆核與每日摘要

目的

將對話產生的候選事件轉為可追溯的正式生活紀錄，並生成不補造資料的每日摘要。

Trigger

WF-01 完成後產生 event_candidate、照護者開啟待覆核事件、每日摘要排程到期，或正式事件被修正、拒絕或刪除。

Happy Path

1. Extractor 產生事件類型、event_time、evidence_text、confidence 與 source_id。

2. Schema、ownership、同意及 tenant／elder 權限檢查。

3. 高信心且低風險事件依 Policy 進入 VERIFIED；其餘進 NEEDS_REVIEW。

4. 照護者可確認、修正或拒絕，系統保存修正前後版本。

5. 排程以日期與 elder_id 讀取可用正式事件。

6. Summary Workflow 生成 DRAFT 摘要；沒有資料的欄位標示「未提及」。

7. 每個摘要重點綁定至少一個 source event_id。

8. Schema 與 Safety 通過後保存專業照護版摘要。

9. 若事件後續修正，受影響摘要標記 STALE／REBUILD_REQUIRED，重新產生新版本。

分支與恢復

• 用藥內容只記錄長者陳述，不判斷正確性。

• 來源衝突標記 DATA_CONFLICT，等待人工處理。

• 當日無事件顯示資料不足，不生成虛構摘要。

• 摘要排程失敗最多重試三次，之後進 DLQ 並告警。

• 事件被拒絕後不得進入摘要、家屬報表或 Graph。

Idempotency

摘要 idempotency_key＝elder_id＋summary_date＋summary_type＋source_version。

對應需求與 UX

US-B01～B04、US-C02、US-K01；04 文件 6.5、6.6、7.2、8.5。

完成證據

展示一筆候選事件從 Needs Review 經修正後重建每日摘要，且來源 event_id 可回查。

# 十、WF-03｜確認式記憶與 Graph 投影

目的

只將長者或授權照護者確認的穩定偏好、重要關係與固定作息保存為長期記憶，並安全同步至 Graph DB。

Happy Path

1. Extractor 判斷內容是否符合候選記憶類型。

2. 建立 CANDIDATE，保留來源事件、擷取信心與版本。

3. 介面詢問「記住／不要記／稍後再說」。

4. 長者選擇記住後，狀態轉 CONFIRMED。

5. 在同一交易中將正式記憶寫入 RDS、狀態轉 ACTIVE，並寫入 Outbox Event。

6. Graph Projector 依 elder_id／tenant_id 建立或更新 node／edge。

7. 投影成功標記 SYNCED；下一輪只檢索 ACTIVE 且權限相符的記憶。

分支與恢復

• 不要記：轉 REJECTED，不寫正式記憶。

• 稍後再說：轉 DEFERRED，不得被檢索。

• Graph 失敗：RDS 記憶仍有效，Graph-dependent query 暫時降級。

• 記憶衝突：先詢問或送人工覆核，不自動判定新舊真偽。

• 更正建立新版本，舊版本轉 INACTIVE。

• 刪除後 Graph 與索引同步失效。

Retry／Compensation

Graph 投影依同一 outbox_event_id 冪等重試；超過上限進 DLQ。禁止 RDS 與 Graph 無保護雙寫。

對應需求與 UX

US-D01～D04、TE-GR01～GR03；04 文件 6.4、8.2。

完成證據

展示「林阿嬤 → 女兒 → 每週日通話」兩層關係、重送不重複，以及停用後不再引用。

# 十一、WF-04｜日照照服員多長者閉環

目的

讓機構照服員從同據點概覽快速找到需要處理的長者，完成摘要、事件覆核與關懷待辦。

Happy Path

1. 驗證照服員角色、tenant 與據點授權。

2. 讀取同據點已授權長者，產生林阿嬤與張阿姨卡片。

3. 每張卡顯示最後互動、今日互動次數、摘要狀態、待覆核數與未完成待辦。

4. 點擊林阿嬤後再次驗證 elder scope。

5. 顯示摘要、事件時間軸、已確認記憶及待覆核內容。

6. 照服員確認、修正或拒絕事件。

7. 受影響摘要、Graph 投影與陪伴需求分析標記重建。

8. 照服員可將經確認事項轉為關懷待辦。

分支與恢復

• 無資料顯示 Empty，不跨 tenant 補滿。

• 權限變更立即停止顯示，不保留敏感快取。

• 同時修改以 expected_version 檢查，衝突時提示重新載入。

• 重送同一 review_command_id 不得重複建立版本或待辦。

對應需求與 UX

US-B03、US-B04、US-C01、US-C02、US-C04；04 文件 6.5、7.2、8.3、8.5。

完成證據

照服員只看到幸福日照中心的林阿嬤與張阿姨，可修正一筆事件並建立待辦。

# 十二、WF-05｜居服員派案與服務紀錄

目的

讓居服員依今日行程與有效派案進入正確長者，查看服務所需資料並完成服務後紀錄。

Happy Path

1. 驗證居服員身份、機構、派案與時間範圍。

2. 顯示今日服務行程與有效派案清單。

3. 居服員選擇陳伯伯服務卡。

4. 再次驗證 assignment_id、elder_id、有效期間與服務範圍。

5. 顯示服務時間、上次服務摘要、待追蹤事項及最小必要資料。

6. 開始服務後派案狀態轉 IN_PROGRESS。

7. 服務後新增專業紀錄、覆核當日事件或建立追蹤事項。

8. 驗證必填欄位後轉 COMPLETED，返回今日行程。

分支與恢復

• 派案取消或過期：顯示 Assignment Expired，不顯示敏感摘要。

• 今日無派案：顯示今日無服務安排。

• 多位長者依行程排序，不以醫療或陪伴分數排名。

• 網路中斷的離線草稿能力由後續 Security 與技術 Spike 決定；未定案前不得假設可離線保存敏感資料。

• 服務紀錄使用 assignment_id＋service_date＋record_type 去重。

對應需求與 UX

US-C01、US-C02、US-C04、NFR-H01；04 文件 6.6、7.2、8.4、8.5。

完成證據

居服員可從行程進入陳伯伯並完成一次服務紀錄；失效派案不可讀取敏感內容。

# 十三、WF-06｜家屬每日／週／月報表與通知

目的

將經授權、允許分享且必要時已覆核的內容發布至家屬 App／Web，並透過 LINE／Email 提醒；通知失敗不得影響已發布報表。

Happy Path

1. 依 elder_id、family_actor_id、consent_version 與 share_scope 檢查授權。

2. 每日報表讀取當日可分享事件；週／月報表只彙整期間內已發布資料。

3. 產生 DRAFT 家屬版內容，不包含逐字稿、未覆核事件、內部筆記、ASR 信心或診斷式分數。

4. 低敏感內容經規則檢查後可直接發布；敏感內容轉 NEEDS_REVIEW。

5. 專業照護者核准後轉 PUBLISHED，建立唯一 report_id 與版本。

6. App／Web 立即可查看最新 Published 版本。

7. 依設定建立 LINE／Email notification job。

8. 發送成功轉 SENT；家屬開啟後記錄 OPENED。

分支與恢復

• 無足夠資料：顯示資料不足，不補造內容。

• 通知失敗：報表維持 Published，只重試通知。

• 報表更新：同一 report_id 建立新版本，舊通知導向最新可見版本。

• 報表撤回：轉 WITHDRAWN，安全連結立即失效。

• 同意撤回：停止新報表與通知；舊資料依 Policy 隱藏或刪除。

• 無權限時不透露長者姓名或報表是否存在。

Retry／Idempotency

通知最多重試三次。notification idempotency_key＝report_id＋version＋recipient＋channel＋scheduled_at；報表 idempotency_key＝elder_id＋period_start＋period_end＋report_type＋source_version。

Human Approval

陪伴需求、家庭衝突、健康、財務、創傷及其他敏感內容發布前必須人工核准。

對應需求與 UX

US-C03、US-C05、NFR-H01～H03、NFR-Q03；04 文件 6.7、6.8、7.3、8.6、8.7、10。

完成證據

App 顯示陳伯伯的一份 Published 每日摘要；LINE 或 Email 實際收到通知；通知失敗時 App 仍可查看且不重複建立 report_id。

# 十四、WF-07｜同意撤回與資料刪除

目的

讓長者或合法授權人撤回特定用途，立即停止新處理，並依 Policy 完成主資料、衍生資料、Graph、索引與安全連結處理。

Happy Path

1. 驗證身分、代理關係、elder_id 與可撤回範圍。

2. 顯示影響範圍與不可逆項目，取得再次確認。

3. 將 consent 狀態轉 REVOKED，保存 consent_version 與 effective_at。

4. 立即停止建立新記憶、分析、主動 Trigger、家屬報表與通知。

5. 取消尚未執行的排程與安全連結。

6. 建立 deletion_job，列出主資料、衍生事件、摘要、記憶、訊號、Graph、索引、快取與通知工作。

7. 各服務依 deletion_job_item 冪等處理並回報。

8. 全部成功轉 COMPLETED；部分失敗轉 PARTIAL_FAILURE，重試或人工處理。

分支與恢復

• 只撤回用途、不要求刪除：停止新增並依 Policy 隱藏或保留既有資料。

• Graph／索引刪除失敗：所有讀取先由 consent gate 阻擋，背景持續清理。

• 刪除期間新事件到達：因 consent_version 不符而拒絕。

• deletion_request_id 唯一，每個 deletion_job_item 可重跑。

對應需求與 UX

US-A06、US-D04、NFR-H03；04 文件 6.9、7.3。

完成證據

撤回家屬分享後新通知立即停止、既有安全連結失效；Graph 清理失敗也不造成前台繼續可讀。

# 十五、WF-08｜主動式個人化陪伴

目的

在長者明確同意、適合時段與資料安全條件成立時，由系統動態發起低風險陪伴；長者可拒絕、換題、暫停或稍後再聊。

Happy Path

1. 建立 Trigger，保存 source_id、owner、expires_at、idempotency_key 與 policy_version。

2. 到期時檢查主動陪伴同意、靜默時段、每日上限、cooldown、裝置、Session、拒絕紀錄與來源狀態。

3. 不符合時轉 BLOCKED 並保存 blocked_reason。

4. 低風險且符合條件時轉 ELIGIBLE；敏感來源轉 APPROVAL_REQUIRED。

5. 必要時由專業照護者核准、修改或拒絕。

6. Topic Ranker 只使用已確認記憶、已覆核事件、時間情境與允許話題。

7. Generator 產生一至兩句、一次一題的動態開場。

8. Safety Evaluator 檢查 ownership、醫療紅線、隱私、敏感內容與拒絕偏好。

9. 轉 READY 後播放；長者可接受、拒絕、換題、停止或稍後再聊。

10. 稍後再聊建立新 follow_up_plan，但到期仍重新通過 Eligibility。

分支與恢復

• 長時間未互動只能作為低權重候選，不能單獨推論孤獨或危險。

• 長者拒絕後立即停止，不繼續追問或產生負面標籤。

• 無回應達 Policy 門檻後結束 Session。

• 敏感主題需人工核准或完全禁止。

• Trigger 過期或來源取消後不得播放。

• Safety 失敗時改用安全結束文案，不重試敏感內容。

Idempotency／Frequency Control

同一 source_id、topic_type 與時間窗只允許一個有效 Trigger；所有重試與 follow-up 仍受每日上限、最短間隔及拒絕紀錄約束。

對應需求與 UX

US-N01～N07、TE-PRO01、US-F01；04 文件 P2 主動陪伴設定與歷史。

完成證據

在林阿嬤同意且允許時段內，以已確認的「每週日等女兒電話」動態發起一次低風險關懷；展示 Eligibility trace，以及長者說停止後流程立即結束。

# 十六、跨工作流事件與責任邊界

• VoiceSessionCompleted：WF-01 發布；WF-02 可消費建立候選事件。

• EventVerified／EventCorrected／EventRejected：WF-02 發布；摘要、Graph、陪伴需求與家屬報表依狀態處理。

• MemoryConfirmed／MemoryDeactivated／MemoryDeleted：WF-03 發布；Graph 與檢索投影消費。

• DailySummaryReady：WF-02 發布；專業照護端顯示，WF-06 評估是否產生家屬版。

• ReportPublished／ReportWithdrawn：WF-06 發布；App 與通知服務消費。

• NotificationFailed：通知服務發布；WF-06 重試或轉人工處理，不回滾報表。

• ConsentRevoked：WF-07 發布；所有工作流停止對應用途。

• AssignmentChanged：派案服務發布；WF-05 更新可見範圍與行程。

• ProactiveTriggerCreated／Blocked／Completed：WF-08 發布；照護者追溯頁與評估流程消費。

事件名稱在 10 Contract 文件前屬概念名稱，不視為最終 API 或 Topic 命名。

# 十七、可觀測性與告警最低要求

• 每個工作流都有 workflow_instance_id、trace_id、current_state、attempt_no、started_at、updated_at。

• 量測語音各階段延遲、摘要完成時間、Graph 投影延遲、通知成功率、DLQ 數量、刪除完成率與 Trigger 阻擋原因。

• 告警至少涵蓋摘要超時、Graph DLQ、通知重試耗盡、刪除部分失敗、跨 tenant 授權拒絕異常增加及主動陪伴安全攔截。

• Demo 技術證據頁需能以 trace_id 串起一次正常流程與一次失敗／恢復流程。

• 不將「沒有錯誤日誌」當作成功證據；成功狀態也需有完成事件與資料版本。

# 十八、測試矩陣

18.1 Happy Path

• 林阿嬤國臺混語語音 → 事件 → 記憶確認 → Graph → 下輪引用。

• 日照照服員概覽 → 林阿嬤詳情 → 事件修正 → 摘要重建。

• 居服員行程 → 陳伯伯服務 → 紀錄完成。

• 家屬 App 查看 Published 報表 → LINE／Email 開啟。

• 主動陪伴 Eligibility 通過 → 播放 → 正常結束。

18.2 Failure／Recovery

• ASR timeout 後重試成功與重試失敗。

• TTS 失敗但文字仍可用。

• RDS 成功、Graph 投影失敗後重放成功。

• 摘要排程失敗三次進 DLQ。

• LINE 發送失敗但 App 報表仍存在。

• 派案在開啟詳情前失效。

• 刪除工作部分失敗後續重試。

• 主動 Trigger 因靜默時段、拒絕紀錄或同意撤回被阻擋。

18.3 Security／Isolation

• 日照帳號不可取得居家長者資料。

• 居服員不可取得非派案長者資料。

• 家屬不可讀取 Draft／Needs Review／Withdrawn 報表。

• 張阿姨事件與記憶不得進入林阿嬤 Context。

• 修改 elder_id、tenant_id、report_id 或安全連結參數無法越權。
