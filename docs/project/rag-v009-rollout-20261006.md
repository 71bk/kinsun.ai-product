## Complete embedding inputs

The longest original replacement contained 5,726 characters. A real Vertex call with automatic truncation disabled rejected it for exceeding the embedding input limit. Google documents a 2,048-token limit and an automatic-truncation default; see [Vertex embedding inputs](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/embeddings/get-text-embeddings) and [Gemini embedding model limits](https://ai.google.dev/gemini-api/docs/models/gemini-embedding-001).

The repair CLI now defaults to a 1,500-character budget. It packs whole table rows, diagrams and regions; repeats page context and shared notes; and keeps the last and first table rows across page boundaries together without filling empty cells. An oversized atomic unit fails. This character budget is not a tokenizer guarantee. The document adapter also sends Vertex `auto_truncate=False` and rejects missing, malformed or non-false truncation statistics. Developer API requests omit the Vertex-only option.

55 original parent chunks produce 110 source-bound fragments; 603 records are unchanged. All 110 new vectors were generated with the existing `gemini-embedding-001` / `RETRIEVAL_DOCUMENT` / 1,024-dimensional profile. Every new Vertex response reported `truncated=false`; the largest reported input was 1,173 tokens. The other 603 vectors were reused from the validated v008 cache. Historical truncation statistics for those reused vectors were not independently verified.

The [source package](../../data/rag-layout/v001/README.md) retains original PDF hashes, metadata, row/cell relationships and two explicit omitted blocks. `needs_review` / `not_completed` remain unchanged. The whole-corpus layout exclusions fall from 70 to 15; professional general-information admission changes from 464 / 55 excluded to 519 / 0 excluded. Elder, family and administrator admission is unchanged. These are structural/admission counts, not semantic accuracy scores.
