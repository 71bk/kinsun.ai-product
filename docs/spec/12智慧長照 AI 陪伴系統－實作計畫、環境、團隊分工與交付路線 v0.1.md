# 一、文件目的

本文件把前述產品、工作流、Domain、安全、AWS 架構、Agent、Contract 與測試設計轉成五人團隊可以直接執行的工程計畫。它回答：誰負責什麼、程式放哪裡、在哪個環境整合、先做哪一條 Critical Path、什麼時候 Freeze、怎樣判斷完成，以及完整產品架構如何分階段實作。

本文件採「完整架構先定義、實作分階段交付」。Target Architecture 不因黑客松縮小而消失；Hackathon Build Profile 只決定本次真正部署、可 Mock 或延後的部分。

# 二、交付原則

1. Vertical Slice 優先：先讓一條林阿嬤流程端到端可運作，再擴充功能面。

2. Contract First：前後端、Agent、Tool、Event 與 Worker 開工前先鎖定最小 Contract。

3. Trunk-Based：短生命週期 Branch、每日合併、主幹保持可部署。

4. One Owner, One Backup：每個元件有單一 Owner 與備援者，避免無人負責或單點知識。

5. Integration Daily：不接受最後一天才整合。

6. Security Is Functional：權限、同意、資料隔離、未確認記憶與 Published Gate 都是功能，不是最後補強。

7. Observable by Default：每條流程從第一天就有 trace_id、state、reason_code 與基本指標。

8. Mock with Boundary：可 Mock 外部服務或延後功能，但不可 Mock 權限、同意、資料隔離與正式狀態規則。

9. Demo Freeze：Freeze 後只修 P0／P1，不再臨時加功能。

10. Evidence over Claim：每個完成項目必須附測試、畫面、Trace 或可重跑指令。

# 八、Branch 與版本策略

## 8.1 Branch

• main：永遠可建置、可部署至 Dev。

• feature/<ticket>-<short-name>：目標一日內合併，最長不超過兩日。

• fix/<ticket>-<short-name>：缺陷修正。

• release/<version>：只在 Demo Freeze 或正式 Release 使用。

## 8.2 Pull Request

PR 必須小於可審查範圍，包含：目的、Contract 影響、測試、Screenshot／Trace、Rollback Notes、Known Risk。

至少一位非作者核准；Security、Contract 或 IaC 變更需對應 Owner 核准。

## 8.3 Commit／Tag

• Conventional Commit 類型：feat、fix、refactor、test、docs、chore、infra、contract。

• Demo Candidate Tag：demo-rc.N。

• Final Demo Tag：demo-v1.0.0。

• Model／Prompt／Policy／Dataset 版本與 Git Tag 一起記錄。

# 九、開發環境

## 9.1 Local

Docker Compose 或 Local Emulator 提供 PostgreSQL、Queue Stub、Object Storage Stub；Agent、Speech 與外部通知可切 Mock／Sandbox。

使用完全合成或去識別資料。

## 9.2 Shared Dev

每次 main 合併後自動部署。

用途：前後端聯調、Agent Tool、WebSocket、Graph／Search Spike。

允許重設資料，不作最終 Demo 證據。

## 9.3 Staging／Demo

接近 Target Architecture，固定 Persona、Seed、Contract、Prompt、Policy、Model 與通知 Sandbox。

只有受控 Migration 可改資料；所有 Demo Rehearsal 與失敗恢復在此執行。

## 9.4 Production

黑客松期間可不開放真實長者使用；正式產品階段才建立 Production Account／VPC／Data Governance 與 Release Gate。

## 9.5 環境隔離

• AWS Account 優先：shared-services、dev、staging、prod；資源不足時至少以 Account／VPC／IAM／Prefix 分離。

• S3 Bucket、KMS Key、Secrets、Cognito Pool、Database、Queue、Index、Graph Endpoint 不跨環境共用。

• 不從 Production 複製資料到 Dev。

# 十、設定與 Secret

• 非敏感設定：版本化 Config／Environment Variable。

• Secret：AWS Secrets Manager／Parameter Store SecureString。

• Local 使用 .env.example，不提交真實 .env。

• Model ID、Prompt Version、Policy Version、Feature Flag 可獨立切換。

• 每個 Environment 有明確 ALLOWED_ORIGINS、LOG_LEVEL、DATA_RETENTION、NOTIFICATION_MODE。

• Demo 使用專用 Test Recipient Allowlist，避免誤寄。

# 十一、Infrastructure as Code

建議使用 AWS CDK 或 Terraform，五人團隊只選一套，不混用。

IaC 模組：

• Network／VPC／Security Group。

• Cognito／IAM／KMS／Secrets。

• ECS／ALB／API Gateway／WebSocket。

• Aurora／S3。

• EventBridge／SQS／DLQ／Scheduler／Step Functions。

• OpenSearch／Neptune。

• AgentCore Runtime／Gateway 相關部署設定。

• CloudWatch Log、Metric、Alarm、Dashboard。

規則：

• 禁止 Console-only Critical Resource。

• 手動建立的 Spike Resource 必須在 24 小時內轉 IaC 或標記可刪除。

• IaC Plan／Diff 在 PR 顯示。

• 每個 Stack 有 Owner、Cost Tag、Environment Tag 與 Removal Policy。

# 十四、Definition of Ready

Task 進入 In Progress 前：

□ 使用者價值與 Actor 清楚。

□ Input／Output／State／Error 已定義。

□ Contract 或 Stub 已存在。

□ Owner／Backup／Dependency 已確認。

□ 測試與安全負向案例已寫出。

□ 是否可 Mock、何時替換已說明。

□ 不存在尚未決定的 Critical Product Rule。

# 十五、Definition of Done

□ Code 已合併 main，無長期私人 Branch。

□ Unit／Contract／必要 Integration Test 通過。

□ Authorization、Consent、Cross-Elder Negative Test 通過。

□ Schema、Error、Idempotency、Version 規則符合 10 文件。

□ Trace／Log／Metric 可找到。

□ UI 有 Loading、Empty、Error、Forbidden／Expired 狀態。

□ 文件、ADR 或 Runbook 已更新。

□ Staging 可重跑，無手動改資料庫才能成功。

□ Demo Evidence 已附上。

□ Owner 與 Backup 都能說明如何操作與恢復。

2. ElderScope／Consent／Core Domain State。

3. Voice Session／ASR／Transcript Confirmation。

4. Orchestrator／Companion／Safety。

5. Session Completed Event。

6. Event／Memory Candidate。

7. Memory Confirmation＋Outbox。

# 二十五、Demo Freeze 規則

Freeze 時點：正式展示前至少 24 小時；可行時提前 48 小時。

Freeze 後允許：

• P0／P1 修復。

• 文案、講稿與不影響 Contract 的展示調整。

• Feature Flag 關閉不穩功能。

Freeze 後禁止：

• 新增 Agent、Database、AWS Service 或主要 Feature。

• 修改 Event／API Breaking Contract。

• 更換未評估模型、Prompt、Policy 或 Dataset。

• 臨時把真實個資加入 Demo。

Release Candidate 必須記錄：Git Tag、Image Digest、Migration Version、Contract、Prompt、Policy、Model、Dataset、Seed、Environment、Known Risks。

# 二十七、風險與緩衝

R-01｜臺語 ASR 未達門檻

處理：低信心確認、預錄 Golden Audio、文字輸入備援；不可假裝辨識正確。

R-02｜AgentCore／Bedrock Latency

處理：縮短 Context、三步上限、較快模型、固定安全 Fallback。

R-03｜Neptune／OpenSearch 建置耗時

處理：先用 Adapter／Local Projection 完成 Contract，再替換；Graph 隔離規則不可省略。

R-04｜LINE 帳號／外部審核

處理：Sandbox／Email Test Recipient；App 是正式報表來源。

R-05｜五人並行造成整合延遲

處理：Contract Mock、每日 Integration Window、WIP Limit。

R-06｜功能太多

處理：Critical Path、Feature Flag、P0／P1／P2 分層；Day 8 後不再加新主流程。

R-07｜AWS 成本突增

處理：Budget Alarm、Auto-stop、TTL Tag、Serverless／On-demand、刪除 Spike Resource。

R-08｜Demo 網路不穩

處理：正式雲端主路徑＋錄影＋Local Read-Only Evidence；安全與權限不可改用假的成功畫面。
