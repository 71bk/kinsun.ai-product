# **一、文件目的與邊界**

本文件回答：每一種角色進入系統後看到哪些頁面、如何完成主要任務，以及錄音、等待、資料不足、低信心、權限不足、通知失敗與授權撤回時，介面如何回應。

本文件不決定 AWS 服務、資料表、API、事件格式或 Agent 內部設計；那些內容由後續 Workflow、Domain、System、Agent 與 Contract 文件定義。

# **二、UX 設計原則**

1. Voice First：長者主要以語音操作，不要求打字或理解複雜選單。

2. 一次一個主要操作：長者端每個畫面只保留一個主要行動。

3. 狀態可感知：待機、錄音、辨識、生成、播放、失敗都要同時提供視覺與語音提示。

4. 不責怪使用者：聽不清楚、逾時或服務失敗時，文案不得暗示長者操作錯誤。

5. 確認後成為事實：候選記憶、AI 擷取事件、陪伴需求與家屬分享內容，必須清楚區分未確認、待覆核與已發布。

6. 角色最小權限：日照照服員、居服員、家屬與管理者只看到完成任務所需資料。

7. 同一資料，多種呈現：同一 report_id 可在家屬 App／Web、LINE 與 Email 呈現不同長度，但正式內容只保存一份。

8. 可復原：重要操作須可取消、返回、修正或撤回，不讓使用者卡在流程中。

9. 不做醫療判斷：介面不得使用確診、疾病機率、孤獨分數或醫療紅黃綠燈。

10. 無資料就是無資料：沒有紀錄時顯示未提及或資料不足，不用 AI 補造內容。

# **三、角色、場域與入口**

## **3.1 長者**

場域：日照中心、社區關懷據點或家中。

主要入口：語音互動首頁。

主要任務：開始對話、理解狀態、確認候選記憶、管理同意與偏好。

## **3.2 日照中心照服員**

場域：同一日照中心或社區據點。

主要入口：同據點多長者概覽。

主要任務：查看林阿嬤與張阿姨等被授權長者、進入詳情、覆核事件、查看摘要與建立待辦。

## **3.3 居家服務員／居服員**

場域：依派案前往不同長者家中。

主要入口：今日服務行程／派案長者清單。

主要任務：查看服務時段、上次服務摘要、待追蹤事項、進入陳伯伯詳情並完成專業紀錄與覆核。

## **3.4 家屬**

場域：遠端使用手機或網頁。

主要入口：家屬 App／Web 首頁；LINE／Email 通知可導入指定報表。

主要任務：查看已發布的每日摘要、週報、月報、歷史重要事件及通知設定。

限制：不能修改事件、記憶、陪伴需求、照護內部筆記或專業待辦。

# **六、核心 User Flow**

## **6.1 長者首次同意流程**

首次進入

→ 選擇語言與稱呼

→ 說明錄音、逐字稿與生活事件用途

→ 分別選擇長期記憶、陪伴需求分析、主動陪伴與家屬分享

→ 顯示選擇摘要

→ 使用者確認

→ 進入語音首頁

*拒絕任何選項時，仍可繼續被允許的基本陪伴功能；介面需清楚說明哪些功能不會啟用。*

## **6.2 語音互動正常流程**

待機

→ 點擊大按鈕開始錄音

→ 顯示正在聽

→ 使用者結束說話

→ 正在辨識

→ 正在整理回覆

→ 播放簡短回覆

→ 顯示此次擷取的生活事件

→ 如有候選記憶，進入記憶確認

→ 返回待機

## **6.3 ASR 低信心確認流程**

ASR 發現人物、日期、否定或用藥關鍵欄位信心不足

→ 顯示系統聽到的關鍵內容

→ 提供「是」「不是／重說」兩個主要選項

→ 確認後繼續事件擷取

→ 否認或再次不清楚時不寫入正式事件或記憶

## **6.4 候選記憶確認流程**

系統產生候選記憶

→ 用一至兩句說明要保存的內容與用途

→ 提供「記住」「不要記」「稍後再說」

→ 記住：寫入正式記憶並顯示成功

→ 不要記：不保存，回到對話

→ 稍後再說：保持候選狀態，不在後續對話引用

## **6.5 日照照服員流程**

照服員登入

→ 進入幸福日照中心多長者概覽

→ 看到林阿嬤、張阿姨的最後互動、互動次數、摘要狀態與待覆核數

→ 點擊林阿嬤

→ 查看每日摘要與時間軸

→ 開啟待覆核事件

→ 修正或確認

→ 受影響摘要與 Graph 標記重建

→ 建立關懷待辦或完成處理

## **6.6 居服員流程**

居服員登入

→ 查看今日服務行程與有效派案長者

→ 選擇陳伯伯的服務卡

→ 查看服務時間、上次服務摘要與待追蹤事項

→ 進入陳伯伯詳情

→ 查看今日事件與既有記憶

→ 完成本次服務紀錄或覆核

→ 建立後續追蹤

→ 返回今日行程

*沒有有效派案時顯示今日無服務安排；無權限或派案失效時不得顯示長者資料。*

## **6.7 家屬報表與通知流程**

每日摘要完成

→ 分享同意與權限檢查

→ 產生家屬版報表

→ 狀態由 Draft／Needs Review 轉為 Published

→ 保存於家屬 App／Web

→ 依家屬設定發送 LINE／Email 簡短通知

→ 家屬點擊安全連結

→ 通過身份與授權驗證

→ 開啟指定每日摘要或週／月報表

→ 可返回報表中心查看歷史

*通知失敗時，App／Web 內 Published 報表仍可查看；系統只重試通知，不重複建立 report_id。*

## **6.8 家屬週報／月報流程**

排程到期

→ 彙整期間內已發布摘要與可分享事件

→ 無資料欄位標示未提及或資料不足

→ 產生報表版本

→ 必要時專業照護人員覆核

→ 發布至家屬報表中心

→ 依通知頻率發送提醒

## **6.9 同意撤回與刪除流程**

長者或授權人進入資料控制

→ 選擇撤回家屬分享、長期記憶、陪伴分析或主動陪伴

→ 顯示影響範圍

→ 再次確認

→ 立即停止新增對應資料與通知

→ 未使用安全連結失效

→ 依 Policy 啟動資料刪除或隱藏流程

→ 顯示處理狀態與完成通知

# **七、頁面狀態規格**

## **7.1 長者語音首頁狀態**

• Idle：顯示「按一下開始說話」。

• Recording：顯示明顯錄音指示、結束按鈕與語音提示。

• Processing ASR：顯示「我正在聽清楚你的話」。

• Generating：顯示「我正在整理回答」。

• Playing：顯示目前播放內容與重新播放。

• Low Confidence：顯示關鍵內容確認。

• Timeout：顯示可重試，不責怪使用者。

• Offline：顯示網路異常與稍後再試。

• Permission Denied：白話引導開啟麥克風。

## **7.2 專業照護端狀態**

• Loading：使用骨架畫面，不顯示過期資料假裝完成。

• Empty：今日無互動、無摘要或無派案。

• Needs Review：清楚顯示待覆核數量與原因。

• Updated：顯示最後更新、修正者與版本。

• Permission Denied：不顯示長者姓名或任何敏感內容。

• Assignment Expired：居服員派案已失效，提供返回行程入口。

• Data Insufficient：顯示資料不足，不產生陪伴結論。

## **7.3 家屬端狀態**

• No Report：尚未產生報表。

• Draft／Needs Review：家屬不可見。

• Published：正常顯示。

• Withdrawn：顯示此報表已撤回，不保留舊敏感內容。

• Notification Failed：App 仍顯示報表，設定頁顯示通知異常。

• Authorization Expired：安全連結失效，要求重新登入或聯絡照護單位。

• Consent Revoked：停止顯示新內容，依政策處理舊報表。

• Data Insufficient：顯示資料不足，不用空白或推測補滿。

# **八、低保真 Wireframe 規格**

## **8.1 長者語音首頁**

頂部：長者稱呼、目前語言、簡單設定入口。

中央：單一大型語音按鈕。

按鈕下方：目前狀態文字與簡短圖示。

底部：重新播放、停止、資料與同意入口。

不得在首頁塞入長列表、複雜導覽或多個同等重要按鈕。

## **8.2 候選記憶確認**

標題：要讓我記住這件事嗎？

內容卡：以白話顯示候選記憶與用途。

主要操作：記住。

次要操作：不要記、稍後再說。

提供語音朗讀，不顯示技術信心分數。

## **8.3 日照多長者概覽**

頂部：據點名稱、日期、搜尋與篩選。

長者卡：姓名／虛擬代稱、最後互動、今日次數、摘要狀態、待覆核數。

主要操作：查看詳情。

禁止跨長者健康或陪伴分數排名。

## **8.4 居服員今日行程**

頂部：日期、今日服務數、同步狀態。

行程卡：服務時間、長者、服務地點、派案狀態、上次摘要、待追蹤事項。

主要操作：開始／查看本次服務。

派案失效卡不得顯示敏感摘要。

## **8.5 專業照護者長者詳情**

頁首：長者基本資料、授權範圍、最後更新。

分頁：今日摘要、時間軸、已確認記憶、待覆核、關懷待辦。

右側或底部：資料來源、版本與更新狀態。

日照與居服模式共用主要元件，但依角色顯示不同服務資訊與操作。

## **8.6 家屬首頁**

頂部：被授權長者、最後更新與通知入口。

第一區：今日摘要。

第二區：本週概覽。

第三區：最新重要事件。

主要操作：查看完整報表。

底部：歷史報表、通知設定、聯絡長者／照護單位。

## **8.7 家屬報表詳情**

標題：日期或期間、發布時間、是否更新。

內容：飲食、活動、睡眠、社交、重要事件；無資料標示未提及。

可顯示關懷式建議，例如「有空時可主動聯絡」，不得顯示診斷或疾病機率。

不顯示逐字稿、未覆核事件、ASR 信心或照護內部筆記。

# **九、權限矩陣**

長者：查看自己的對話狀態、同意與候選記憶；可拒絕、撤回與刪除。

日照照服員：查看所屬據點且被授權長者；可覆核事件、查看專業資訊與建立待辦。

居服員：查看有效派案範圍內長者；可處理服務相關紀錄與覆核，不能查看未派案長者。

家屬：查看分享授權範圍內的 Published 報表與可分享事件；不能修改正式事件、記憶或待辦。

管理者：依職責管理來源、版本、Policy、權限與系統狀態；不得因管理介面繞過資料最小化。

# **十、家屬報表與通知 UX 決策**

1. App／Web 是正式查看與歷史保存介面；LINE／Email 是通知與導流通路。

2. 同一份正式報表只有一個 report_id，不因通路不同產生三份資料。

3. LINE／Email 預覽只放必要資訊，完整內容需登入或通過安全連結驗證後查看。

4. 報表更新後，家屬端顯示最新版本與更新時間；舊通知導入同一 report_id 的最新可見版本。

5. 通知失敗不影響報表發布；報表撤回或授權失效會使安全連結失效。

6. 家屬可設定每日、每週、每月、LINE、Email、通知時間與靜默時段。

7. 每週／每月報表只彙整已記錄、已覆核或已允許分享的資料，不做醫療趨勢預測。

# **十一、可用性測試計畫**

## **11.1 長者測試任務**

• 找到並開始錄音。

• 理解錄音、辨識、生成與播放狀態。

• 完成一筆低信心確認。

• 接受、拒絕或延後一筆候選記憶。

• 找到同意設定並撤回家屬分享。

## **11.2 日照照服員測試任務**

• 從多長者概覽找到待覆核最多的長者。

• 進入林阿嬤詳情並找到來源事件。

• 修正一筆事件並確認更新狀態。

• 建立一筆關懷待辦。

## **11.3 居服員測試任務**

• 從今日行程找到下一位服務對象。

• 進入陳伯伯詳情並找到上次服務摘要。

• 辨識派案失效與無權限狀態。

• 完成一次服務後紀錄或待追蹤事項。

## **11.4 家屬測試任務**

• 從 LINE／Email 進入正確的每日摘要。

• 找到本週與本月報表。

• 理解資料不足、報表更新與撤回狀態。

• 調整通知頻率與靜默時段。

• 分辨家屬可見資料與專業照護內部資料。
